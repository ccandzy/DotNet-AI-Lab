# MarkdownChunker 验证文档

这份文档专门用于观察 MarkdownChunker 的切分结果。内容包含 YAML、标题、段落、列表、代码围栏和表格。

## 普通段落与重叠

第一段介绍切块目的。较长文档不能直接作为一个整体交给 Embedding 模型，所以需要先按照结构拆成较小而且仍然具有完整语义的文本块。本段用于占用第一个 Chunk 的一部分空间，也特意增加一些说明文字，让后面的新段落能够稳定触发切块边界。

OVERLAP_MARKER：这段完整的小段落应同时出现在相邻的两个 Chunk 中。

第三段用于触发新的 Chunk。它需要足够长，使当前内容超过设定的三百字符上限。切换到新 Chunk 时，上一块末尾带有 OVERLAP_MARKER 的完整段落会被复制过来，从而让两个相邻块共享少量上下文，降低边界处语义突然中断的影响。

第四段说明重叠不是把任意字符串机械截取一百个字符，而是尽量复制完整段落，因此实际重叠长度可能小于配置值。

## 列表

- 文档先按照标题划分章节。
- 章节内部再按照空行划分段落。
- 普通段落可以组合或继续拆分。
- 代码块和表格属于受保护内容。

## 代码围栏

下面代码中的井号只是字符串内容，不能被误认为新的 Markdown 标题。

```csharp
var headingLikeText = "# 这不是 Markdown 标题";
var steps = new[]
{
    "读取 Markdown 文件",
    "识别标题和段落",
    "生成带来源信息的 Chunk"
};

Console.WriteLine(string.Join(" -> ", steps));
```

代码围栏结束后，这句话重新属于普通 Markdown 正文。

## 表格

| 配置项 | 作用 |
| --- | --- |
| Temperature | 控制生成的随机程度 |
| TopP | 控制候选词采样范围 |
| MaxTokens | 限制最大输出长度 |

表格的表头、分隔行和数据行应当保存在同一个 Chunk 中。
