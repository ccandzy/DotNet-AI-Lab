# 演示前检查与操作清单

## 本轮修复

- 无会话、无有效模型时禁止发送；删除最后一个会话后提示新建。
- 发送开始即锁定会话操作，并固定本次请求所属会话和配置。
- 保存、创建、删除、清空、重命名失败时显示错误并恢复操作状态。
- 用户消息保存失败保留输入；回答保存失败保留页面内容，并排除出后续请求历史。
- 从程序目录加载配置，启动失败后明确提示并退出。
- 知识库未导入、无匹配或检索失败时，明确提示本次使用普通聊天。
- 知识文件支持取消导入；取消或重建失败保留旧索引。
- MCP 通信超时或协议异常关闭连接并清理子进程，允许重新连接。

## 演示前自行准备

1. 提前启动Ollama服务，确认聊天模型和向量模型都可用。仅能使用DeepSeek聊天，不代表知识库的向量服务可用。
2. 打开程序，先用一句简短问题确认选定模型能响应。
3. 导入同目录下的 `demo-knowledge.md`，确认显示“已向量化”后再演示文档问答。
4. 知识索引只保存在内存中，重启程序后必须重新导入文件。
5. 保留一段成功演示录像，以应对现场网络或模型响应较慢的情况。

## 建议演示顺序

1. 普通对话：“请用一句话介绍你自己。”
2. 开启工具：“请调用计算工具计算 125 * 8 + 17。”预期结果为1017。
3. 导入演示文档并开启RAG：“青竹-417工单的处理顺序是什么？”核对回答与文档内容及来源。
4. MCP点击“连接”，选择 `get_current_time`，点击“调用选中 Tool”。

## 超时设置

在 `appsettings.Local.json` 的现有 `Rag` 配置节中按需添加以下字段，勿覆盖其他已有配置：

```json
{
  "Rag": {
    "ImportTimeoutSeconds": 120,
    "RetrievalTimeoutSeconds": 30
  }
}
```

未配置时采用上述默认值。修改后重启生效。MCP单次请求超时保持10秒。
